# _engine.js

## Описание

Чистая геометрия [Observer](index.js.md) без DOM: на вход идут прямоугольники
`{ top, left, width, height }` (подходит и `DOMRect`). Плоские именованные экспорты,
тесты — `node tests/observer.test.mjs`.

## Экспорты

| Функция | Что делает |
|---|---|
| `parse_edge(token)` | `'top'`, `'80%'`, `'120px'`, `'bottom-10%'`, `40` → `{ frac, px }`: позиция = начало + `frac × размер` + `px`. Мусор — предупреждение и `{ 0, 0 }` |
| `parse_line(value, root_default)` | `'top 80%'` → `[край элемента, край root]`; без второго токена root берёт `root_default` |
| `parse_zone(start, end)` | `{ start, end }`; root по умолчанию — `bottom` для start и `top` для end |
| `measure(rect, root, zone, axis)` | `{ a, b }` — линия элемента минус линия root для start и для end |
| `state_of(a, b)` | `a > 0` → `before`, `b < 0` → `after`, иначе `active` |
| `progress_of(a, b)` | `−a / (b − a)`, зажатый в `0…1`. Нулевая или обратная зона — ступенька 0 → 1 на линии start |
| `intersects(r1, r2)` | Строгое пересечение: касание краем не считается |
| `steps(prev, next)` | Переход → список `{ hook, direction, state }`. Перескок `before ↔ after` даёт `on_enter` и `on_leave` подряд |

## Почему `a` и `b`

При прокрутке на δ все прямоугольники во viewport сдвигаются на δ, а root — нет. Поэтому `a`
и `b` уменьшаются одинаково, и их разность `b − a` — длина пути через зону — постоянна. Состояние и
прогресс считаются из текущих rect без кэша позиций. Значит, layout-сдвиги, картинки и
шрифты не требуют ручного `refresh()`, если после них был хоть один кадр прокрутки или
изменение размера.
