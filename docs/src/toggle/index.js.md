## 1. Описание

`Toggle` — универсальный примитив переключения состояния. Один экземпляр обслуживает
**множество независимых триггеров**; по событию (`click` и т.п.) триггер переключается между
состояниями и вместе с собой переводит свои **цели** (targets). Класс приходит на смену
`st_accordion` и достаточно общий, чтобы строить на нём аккордеоны, кнопки-переключатели,
спойлеры, hover-меню и т.п.

**Ключевые принципы:**

- **Только состояние.** Класс лишь меняет атрибут `state` на триггере и целях и вызывает
  пользовательские замыкания. Он **не трогает** `display`/`style` триггеров и целей - весь визуал
  отдаётся CSS (по селекторам `[state="..."]`). Исключения - табы: индикатору (`indicator`)
  пишутся CSS-переменные с координатами активного таба, и лента с прокруткой доводится до
  активного таба (раздел [13](#13-индикатор-и-прокрутка-табов)).
- **Группы - параметром `group`.** Аккордеон (`true`) и табы (`'radio'`) внутри одного экземпляра;
  более сложное взаимоисключение пишется в хуках через `deactivate()` у соседей.
- **Триггеры и цели независимы.** Один target может управляться несколькими триггерами; источник
  направления — состояние самого триггера. События триггера и целей раздельные и асинхронные —
  это позволяет комбинировать цепочки toggle-ров (цель одного может быть триггером другого).
- **Нет зависимостей.** Чистый ES6-класс, экспортируется как ES-модуль.

## 2. Модель: триггеры и цели

```
new Toggle({ trigger: '[trigger]', target: null })
        │
        ├── trigger #1 ──► targets: [ ... ]   (из атрибута target="" или params.target)
        ├── trigger #2 ──► targets: [ ... ]
        └── trigger #N ──► targets: [ ... ]
```

- **Триггеры** ищутся при создании по `params.trigger` (по умолчанию `[trigger]`). На каждый
  вешается обработчик события `params.action`. Появившиеся позже подхватывает `refresh()`.
- **Цели** разрешаются **при каждом переключении** (а не один раз) — см. раздел
  [8](#8-разрешение-целей-target). У одного триггера может быть несколько целей.
- Каждый триггер хранит ссылку на экземпляр через приватный Symbol — доступно через
  `Toggle.find()`.

## 3. Машина состояний

Атрибут `state` (на триггере и на каждой цели) проходит цикл:

```
            activate                    on_activate / on_activated
inactive ──────────────► activating ──────────────────────────────► active
   ▲                                                                   │
   │  on_deactivate /            deactivate                            │
   └──── on_deactivated ◄──── deactivating ◄───────────────────────────┘
```

| Состояние | Описание |
|---|---|
| `inactive` | Выключено (конечное состояние после деактивации) |
| `activating` | Идёт анимация включения (прошёл один `requestAnimationFrame`) |
| `active` | Анимация завершена, включено |
| `deactivating` | Идёт анимация выключения |

### Как происходит переход (внутренняя механика)

Мирроринг механики `Modal`:

1. Решается направление (для `toggle()` — по текущему состоянию триггера).
2. Вызывается хук `before_*` (на старте).
3. Первый `requestAnimationFrame` ставит промежуточное состояние
   (`activating` / `deactivating`) — это запускает CSS-переход.
4. Второй `requestAnimationFrame` запускает `setTimeout(duration * 1000)`.
5. По окончании таймаута ставится финальное состояние (`active` / `inactive`) и
   вызывается хук `on_*`.

Триггер и его цели переводятся **отдельными** проходами (независимые жизненные циклы), но в
рамках одного прохода состояния всех целей меняются «пачкой» в одном `requestAnimationFrame` —
это снижает нагрузку при большом числе целей. Таймер хранится **per-element**, поэтому повторное
переключение прерывает ожидающий финал только нужных элементов.

### allow_interrupt

По умолчанию (`allow_interrupt: false`) переключение, вызванное во время обратной анимации,
игнорируется: `activate` работает только из `inactive`, `deactivate` — только из `active`.

При `allow_interrupt: true` разрешается прервать текущий переход и стартовать обратный
(`activate` из `deactivating`, `deactivate` из `activating`) — для плавного реверса.

## 4. Параметры конструктора

```js
new Toggle(params)
```

Все параметры необязательны.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `trigger` | `string \| function \| Element \| NodeList \| Array` | `'[trigger]'` | Что считать триггерами. Селектор или функция, возвращающая элементы, резолвится при создании и заново в `refresh()`. Готовый список элементов `refresh()` не пересчитывает. |
| `target` | `string \| function \| Element \| NodeList \| Array \| null` | `null` | Цели триггера. Если функция — вызывается как `target(trigger)` при каждом переключении. Если `null` — берётся из атрибута `target=""` триггера. См. раздел [8](#8-разрешение-целей-target). |
| `action` | `string` | `'click'` | Имя DOM-события на триггере. Спец-значение `'hover'` → `mouseenter` включает, `mouseleave` выключает. |
| `duration` | `number` | `0` | Длительность перехода в секундах (= время до установки финального состояния и вызова `on_*`). CSS-`transition` задаётся разработчиком. |
| `allow_interrupt` | `boolean` | `false` | Разрешить прерывание текущего перехода обратным. |
| `anchor` | `false \| true \| 'trigger' \| 'target'` | `false` | Синхронизировать активный триггер с хешем URL (deep-linking). `true` и `'trigger'` пишут в hash id триггера, `'target'` - id панели. См. раздел [12](#12-якорные-ссылки-deep-linking). |
| `keep_history` | `boolean` | `false` | Создавать ли запись в истории на каждое переключение. `false` → `replaceState` (кнопка "назад" уходит со страницы); `true` → `pushState` + реакция на `hashchange` (кнопка "назад" возвращает предыдущий таб). **Включает `anchor: true`, если якорь не задан** (без якоря история хеша бессмысленна); `anchor: 'target'` сохраняется. |
| `group` | `false \| true \| 'radio'` | `false` | Взаимоисключение триггеров **одного экземпляра**. `true` — аккордеон: при активации триггера остальные активные триггеры экземпляра деактивируются (ещё не доигравший `activating` — только при `allow_interrupt: true`), их хуки `before_/on_deactivate(d)` срабатывают как обычно; повторный клик закрывает открытый. `'radio'` — табы: то же, но `toggle()` (и клик) по активному триггеру ничего не делает, и один таб всегда остаётся открытым. Явный `deactivate()` работает в обоих режимах. |
| `indicator` | `string \| Element \| function \| null` | `null` | Элемент, который следует за активным триггером (пилюля, подчёркивание табов). Функция вызывается как `indicator(toggle)` один раз при создании. Индикатор получает CSS-переменные `--indicator-x/-y/-width/-height` и `state="active" \| "inactive"`. `clone()` копирует его вместе с остальными параметрами - для другой ленты переопределяйте `indicator` вместе с `trigger`. См. раздел [13](#13-индикатор-и-прокрутка-табов). |
| `reveal` | `boolean` | `false` | Доводить ли активируемый кликом или из кода триггер до полной видимости в горизонтальной ленте с прокруткой. При переходе по якорю и для стартового активного триггера доводка идёт всегда; при `action: 'hover'` по клику - никогда. См. раздел [13](#13-индикатор-и-прокрутка-табов). |

> **Имена атрибутов фиксированы:** триггеры по умолчанию `[trigger]`, цель — атрибут `target=""`,
> состояние — атрибут `state=""`.

## 5. Хуки жизненного цикла

Хуки делятся на **события триггера** и **события целей** — они независимы.

### События триггера — вызываются 1 раз, аргументы `(trigger, targets)`

| Хук | Когда | `targets` |
|---|---|---|
| `before_activate` | на старте включения | массив целей |
| `on_activate` | после `duration` (включено) | массив целей |
| `before_deactivate` | на старте выключения | массив целей |
| `on_deactivate` | после `duration` (выключено) | массив целей |

### События целей — вызываются **для каждой цели**, аргументы `(target, trigger)`

| Хук | Когда |
|---|---|
| `before_activated` | на старте включения цели |
| `on_activated` | после `duration` (цель включена) |
| `before_deactivated` | на старте выключения цели |
| `on_deactivated` | после `duration` (цель выключена) |

### Инициализация

| Хук | Когда |
|---|---|
| `before_init` | до поиска триггеров и навешивания обработчиков; получает `params` |
| `on_init` | после полной инициализации; получает `params` |

### Привязка контекста

Все хуки (кроме `target`-функции) привязываются к экземпляру через `.bind(this)` — внутри хука
`this` указывает на экземпляр `Toggle`.

## 6. Публичные свойства и методы

### Геттеры

| Член | Возвращает | Описание |
|---|---|---|
| `params` | `object` | Параметры экземпляра (без функций-хуков) |

> Текущее состояние читается прямо из DOM: `el.getAttribute('state')` — отдельного метода нет.

### Методы

Все три принимают `Element`, `NodeList`, `Array` **или** CSS-селектор; применяются к каждому
совпавшему элементу.

#### `toggle(el)`

Переключает направление по текущему состоянию триггера: из `active`/`activating` → деактивирует,
иначе активирует. Это обработчик, навешиваемый по умолчанию.

#### `activate(el)`

Принудительно включает (с учётом guard'а состояния и `allow_interrupt`).

#### `deactivate(el)`

Принудительно выключает (с учётом guard'а состояния и `allow_interrupt`).

```js
tg.toggle('#item');
tg.activate(document.querySelector('[trigger]'));
tg.deactivate('#accordion [trigger]');   // на все совпадения
```

#### `clone(params)`

Создаёт новый экземпляр `Toggle` на основе текущего: параметры и хуки исходного экземпляра берутся
за основу, переданный `params` их переопределяет, а в новый экземпляр добавляется ссылка на
оригинал через параметр `parent`.

В отличие от `Modal.clone()`, DOM не клонируется — `Toggle` не владеет собственными элементами,
поэтому обычно при клонировании переопределяют `trigger` (и при необходимости `target`), чтобы
тот же конфиг применить к другим элементам без повторной привязки к исходным.

```js
const base = new Toggle({ duration: 0.3, on_activate() { /* … */ } });

// та же логика, но на другом наборе триггеров
const copy = base.clone({ trigger: '#sidebar [trigger]' });
```

#### `destroy()`

Разбирает экземпляр: снимает обработчики триггеров и `hashchange` на `window` (`keep_history`), слежение за индикатором (`ResizeObserver`, прокрутка), таймеры переходов и методы `toggle`/`activate`/`deactivate` с триггеров. `state` на триггерах и целях остаётся как есть. Нужен, когда группа живёт меньше страницы - компонент SPA, который уходит со сменой маршрута: без `destroy()` слушатель `hashchange` каждого экземпляра остаётся на `window`.

```js
const tabs = new Toggle({ trigger: '#tabs [trigger]', group: 'radio', anchor: true, keep_history: true });
// компонент снимается
tabs.destroy();
```

#### `refresh()`

Пересканирует `trigger` (селектор или функцию): триггеры, ушедшие из DOM, снимает (обработчики, методы, якорь, слежение индикатора), новые привязывает. Если вкладки отрисовались после создания `Toggle`, а в hash уже их якорь, — открывает нужную. Индикатор пересчитывается. Возвращает экземпляр.

Нужен, когда триггеры перерисовывает App, Vue или свой код: `Toggle` о них не знает.

```js
// вкладки из #for внутри <st-app>
const tabs = new Toggle({ trigger: () => app.querySelectorAll('[role=tab]'), group: 'radio', anchor: 'target' });
app.addEventListener('updated', () => tabs.refresh());
```

Новые триггеры начинают с `state` из разметки (без него - `inactive`). Строку `#for` с `#key` App переносит, не пересоздавая, и её состояние сохраняется.

## 7. Статические методы

### `Toggle.find(element | selector)`

Возвращает экземпляр `Toggle`, связанный с переданным **триггером** (или `undefined`).

```js
const instance = Toggle.find(document.querySelector('[trigger]'));
instance?.deactivate(someTrigger);
```

## 8. Разрешение целей (target)

Цели триггера определяются при **каждом** переключении в таком порядке:

1. `params.target` — если задан:
   - **функция** → вызывается как `target(trigger)`; может вернуть селектор, `Element`,
     `NodeList` или массив;
   - **селектор / Element / NodeList / Array** → используется как есть.
2. Иначе — атрибут `target=""` самого триггера (CSS-селектор).
3. Если ничего не найдено — целей нет, триггер переключает только себя.

Результат приводится к массиву элементов хелпером `elements()` из трейта (без побочных эффектов:
несовпавший селектор → пустой список).

```html
<div trigger target="#panel">Кнопка</div>
<div id="panel" content>…</div>
```

```js
// Цель как замыкание (например, относительно триггера):
new Toggle({ target: trigger => trigger.parentElement.querySelector('.drop') });
```

## 9. CSS-анимация через атрибут state

Единственный механизм визуала — CSS по атрибуту `[state]`. Класс не задаёт `transition`
самостоятельно — это делает разработчик.

```css
/* Спойлер: видим в active/activating, скрыт в inactive/deactivating */
[content] { overflow: hidden; transition: height .3s, opacity .3s; }

[content][state="inactive"],
[content][state="deactivating"] { opacity: 0; height: 0; }

[content][state="active"],
[content][state="activating"]   { opacity: 1; }
```

> **Совет:** разделяя `activating`/`deactivating`, можно задать разные анимации входа и выхода.

## 10. Примеры

### Спойлер по атрибуту `target`

```html
<button trigger target="#more">Подробнее</button>
<div id="more" content>Скрытый текст…</div>
```

```js
import Toggle from './toggle.js';
new Toggle({ duration: 0.3 });   // trigger по умолчанию '[trigger]'
```

### Аккордеон (`group: true`)

```js
new Toggle({
    duration: 0.3,
    trigger: '#accordion [trigger]',
    group: true,          // открытие секции закрывает остальные, повторный клик закрывает текущую
});
```

### Табы (`group: 'radio'`)

```html
<nav>
    <button trigger target="#tab-1" state="active">Первый</button>
    <button trigger target="#tab-2">Второй</button>
</nav>
<section id="tab-1" state="active">…</section>
<section id="tab-2">…</section>
```

```js
new Toggle({
    trigger: 'nav [trigger]',
    group: 'radio',       // клик по активному табу его не выключает
    anchor: true,         // по желанию: активный таб в hash
});
```

Стартовый таб задаётся атрибутом `state="active"` на триггере и его цели - `Toggle` не
перезаписывает уже проставленный `state`.

**Доступность.** У триггера с `role="tab"` `Toggle` сам ведёт `aria-selected` (`"true"` у
активного, `"false"` у остальных), у триггера с атрибутом `aria-expanded` в разметке (аккордеон,
раскрывающийся блок) - `aria-expanded`. Значения меняются сразу при переключении, до конца
анимации. `tabindex` не трогается: навигации стрелками в `Toggle` нет, и без неё вкладки с
`tabindex="-1"` нельзя было бы выбрать с клавиатуры.

```html
<nav role="tablist">
    <button role="tab" trigger target="#tab-1" state="active">Первый</button>
    <button role="tab" trigger target="#tab-2">Второй</button>
</nav>
<button aria-expanded="false" class="faq" target="#answer">Вопрос</button>
```

### Кнопка-переключатель (без целей)

```js
new Toggle({
    trigger: '.switch',
    target: null,                         // переключает только сам триггер
    duration: 0.25,
    on_activate:   () => console.log('on'),
    on_deactivate: () => console.log('off'),
});
```

### Hover-меню (target как замыкание)

В режиме `'hover'` вешайте триггер на **обёртку**, которая DOM-содержит и подпись, и выпадающий
список — тогда наведение на пункты считается «внутри» (`mouseleave` не срабатывает при переходе
на потомка). Триггер на саму подпись закроет меню при наведении на пункты. См. раздел [11](#11-известные-особенности-и-ограничения).

```html
<div class="menu" trigger>
    <div class="menu-trigger">Меню ▾</div>
    <div class="menu-drop"><!-- пункты --></div>
</div>
```

```js
new Toggle({
    action: 'hover',
    duration: 0.2,
    trigger: '.menu',
    target: trigger => trigger.querySelector('.menu-drop'),
});
```

> **Зазор закрывает меню.** Не оставляйте пустого промежутка между подписью и выпадашкой
> (`margin-top` и т.п.) — курсор пройдёт по «дыре» над `body`, сработает `mouseleave`, и меню
> закроется. Используйте смежные элементы (`top: 100%` без отступа) или соедините их `padding`.

### Программное управление и `find`

```js
const tg = new Toggle({ trigger: '[trigger]' });

tg.activate('#item');
console.log(document.querySelector('#item').getAttribute('state'));   // 'activating' → позже 'active'

const inst = Toggle.find(document.querySelector('[trigger]'));
inst.toggle(someTrigger);
```

## 11. Известные особенности и ограничения

### Новые триггеры - через `refresh()`

`params.trigger` резолвится в конструкторе. Элементы, добавленные в DOM позже, `Toggle` сам не
замечает: вызовите `refresh()` после перерисовки (в `<st-app>` - в событии `updated`). Передавайте
триггеры селектором или функцией: готовый список элементов `refresh()` не пересчитывает.

### Цели разрешаются при каждом переключении

В отличие от триггеров, цели вычисляются на каждый вызов — это позволяет `target`-замыканию
учитывать текущий DOM и работать с динамическими элементами.

### Группа — это один экземпляр

`group` действует на триггеры одного `Toggle`. Две независимые группы табов на странице - два
экземпляра с разными селекторами `trigger`. Триггеры, добавленные в DOM позже, попадают в группу
после `refresh()` (см. выше).

### Состояния триггера и целей независимы

Один target, управляемый несколькими триггерами, может рассинхронизироваться с их состояниями —
это сделано намеренно (для комбинирования цепочек toggle-ров).

### hover: учитываются DOM-потомки триггера, а не геометрия

`action: 'hover'` использует `mouseenter`/`mouseleave`. Они **не** срабатывают при переходе курсора
на DOM-потомка триггера (даже если тот спозиционирован вне его рамки). Поэтому для hover-меню вешайте
триггер на обёртку, содержащую и подпись, и выпадашку, и не оставляйте между ними геометрического
зазора (см. пример выше). Если цель — *сосед* триггера, наведение на неё закроет меню.

### Класс не управляет display

После выключения цель остаётся в DOM со `state="inactive"`. Если нужно `display: none` —
задайте это в CSS через `[state="inactive"]`.

## 12. Якорные ссылки (deep-linking)

При `anchor` активный триггер синхронизируется с хешем адресной строки: активация
дописывает `#id`, открытие страницы с `#id` сразу активирует соответствующий триггер. По умолчанию
`anchor` выключен (`false`); `keep_history: true` включает его, если он не задан.

### Какой id попадает в URL

`anchor: true` или `'trigger'` - приоритет у триггера:

1. если у **самого триггера** есть `id` - пишется он;
2. иначе, если у триггера ровно **одна** цель и у неё есть `id` - пишется `id` цели;
3. иначе - триггер в URL не отражается.

`anchor: 'target'` - приоритет у панели: сначала `id` единственной цели, затем `id` триггера.
Ссылку на раздел естественнее давать на панель (`#core-keys`), а не на кнопку вкладки
(`#core-keys-tab`).

Триггеры без подходящего `id` (например, hover-меню без `id` у дропдауна) ничего не пишут в URL.

```html
<!-- id у цели → в URL попадёт #a2 -->
<div trigger target="#a2">Раздел 2</div>
<div id="a2" content>…</div>

<!-- id у самого триггера → в URL попадёт #theme-switch -->
<div class="switch" trigger id="theme-switch"></div>
```

### Поведение кнопки «назад» (`keep_history`)

URL всегда обновляется через `history.*` (никогда через `location.hash`) — поэтому **прокрутки к
элементу не происходит**, а история не засоряется при `keep_history: false`.

| `keep_history` | Метод | Кнопка «назад» |
|---|---|---|
| `false` (по умолчанию) | `replaceState` | уходит со страницы, переключения табов игнорируются |
| `true` | `pushState` + `hashchange` | возвращает предыдущий таб; пустой хеш закрывает текущий |

```js
// Табы с навигацией «назад/вперёд» между ними
new Toggle({ trigger: '#tabs [trigger]', keep_history: true });
```

### Прокрутка к элементу

Страницу `Toggle` не прокручивает. Если нужна прокрутка к элементу - сделайте триггер настоящей
ссылкой `<a href="#id">`: браузер сам проскроллит к нему (это нативное поведение, независимое от
`Toggle`). Если прокрутка не нужна - используйте любой не-`<a>` элемент.

Ленту табов с горизонтальной прокруткой `Toggle` доводит до таба из хеша сам, всегда - см.
раздел [13](#13-индикатор-и-прокрутка-табов).

### Отключение

`anchor: false` полностью выключает работу с URL - поведение как до появления фичи.

## 13. Индикатор и прокрутка табов

### Индикатор (`indicator`)

Элемент, который следует за активным триггером: пилюля под табом, подчёркивание. Визуал и
анимация - в CSS проекта; `Toggle` пишет индикатору координаты активного триггера:

| Переменная | Значение |
|---|---|
| `--indicator-x`, `--indicator-y` | Смещение триггера от `offsetParent` индикатора, с учётом его прокрутки и рамки, `px` |
| `--indicator-width`, `--indicator-height` | Размер триггера, `px` |

и атрибут `state`: `active` - есть за кем следовать, `inactive` - активных триггеров нет
(`group: true` после закрытия последнего, или без группы). При `inactive` координаты остаются
прежними - индикатор можно погасить на месте.

```html
<nav class="tabs">
    <button trigger target="#tab-1" state="active">Первый</button>
    <button trigger target="#tab-2">Второй</button>
    <button trigger target="#tab-3">Третий</button>
    <i class="tabs__pill"></i>
</nav>
```

```css
.tabs { position: relative; display: flex; overflow-x: auto; }
.tabs__pill {
    position: absolute; left: 0; top: 0;
    width: var(--indicator-width); height: var(--indicator-height);
    transform: translateX(var(--indicator-x));
    transition: transform .3s, width .3s, opacity .3s;
}
.tabs__pill[state="inactive"] { opacity: 0; }
```

```js
new Toggle({ trigger: '.tabs [trigger]', group: 'radio', indicator: '.tabs__pill', reveal: true });
```

**Разметка.** Индикатор кладите **внутрь** прокручиваемой ленты, у ленты - `position: relative`.
Тогда индикатор прокручивается вместе с табами и при прокрутке не пересчитывается. Индикатор вне
ленты тоже работает: `Toggle` пересчитывает его на каждом кадре прокрутки.

**Когда индикатор анимируется.** Переезд на другой триггер идёт по `transition` из CSS - в момент
начала активации, вместе с `activating`. Всё остальное индикатор делает **мгновенно**, на время
записи выключая `transition` в inline-стиле:

- первая расстановка при создании - индикатор не "выезжает" из нуля;
- появление после `state="inactive"` - встаёт на место, а не едет от прежнего;
- изменение размеров (`ResizeObserver` на триггерах и родителе индикатора): ресайз окна, подгрузка
  шрифта, показ скрытой панели или модалки с табами;
- прокрутка ленты, если индикатор стоит вне её.

За каким триггером следует: за тем, чья активация началась последней. Выключили его (без группы
или `group: true`) - индикатор переходит к оставшемуся активному, если такой есть.

### Доводка таба до видимости

Если триггер лежит в горизонтальной ленте с прокруткой (`overflow-x: auto | scroll`) и виден в ней
не целиком, лента прокручивается так, чтобы он был виден целиком.

| Активация | Доводка |
|---|---|
| Переход по якорю: хеш при загрузке, `hashchange` при `keep_history` | всегда |
| Стартовый активный триггер (`state="active"` в разметке) | всегда |
| Клик, `activate()` / `toggle()` из кода | при `reveal: true` |
| Наведение (`action: 'hover'`) | никогда - меню прокрутилось бы под курсором |

Таб из ссылки или из разметки выбрал не пользователь, и он может стоять за краем ленты, поэтому
здесь доводка обязательна. Кликнутый таб пользователь видит хотя бы частично - довести его до
полной видимости или нет, решает проект флагом `reveal`.

Что учтено:

- прокручивается **только ближайшая** горизонтальная лента - ни страница, ни внешние области с
  прокруткой, ни вертикаль не двигаются;
- `scroll-padding-inline` ленты: таб не уходит под липкие стрелки или градиент на краю;
- `scroll-snap`: лента прокручивается к точке прилипания, в которой таб виден целиком, - иначе
  браузер "прилепил" бы её к ближайшей точке, и таб снова ушёл бы за край;
- `scroll-behavior: smooth` из CSS ленты работает; быстрые клики подряд не накапливают прокрутку -
  лента приходит к последнему табу. Доводка при загрузке страницы и при показе скрытых табов -
  мгновенная;
- RTL (`dir="rtl"`) - доводка и индикатор работают зеркально;
- табы скрыты (закрытая модалка, свёрнутая панель) - доводка откладывается до показа;
- таб, видимый целиком, ленту не двигает: ни после ручной прокрутки, ни при фокусе с клавиатуры
  (браузер уже прокрутил ленту к фокусу, второго рывка нет);
- таб шире ленты выравнивается по начальному краю.
